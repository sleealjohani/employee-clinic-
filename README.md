# عيادة الموظفين — مستشفى الحديثة العام

منصة عربية وإنجليزية تربط ملف الموظف بمواعيده وزياراته وتحاليله وتطعيماته وطلبات الخدمة. مبنية باستخدام Next.js App Router وReact وTypeScript، وPostgreSQL على Supabase عبر Prisma، ومنشورة على Vercel.

## الاستخدام اليومي

1. يسجّل المدير الدخول بحسابه الحالي. من **الإعدادات** يحدد اسم العيادة، موقعها، الألوان والحركة، أيام وساعات العمل، سعة المواعيد، سياسة الإلغاء، والحقول المطلوبة لاكتمال الملف.
2. من **الموظفين** ينشئ الملفات أو يستورد جدول Excel/CSV بعد معاينة النتائج. الاستيراد يكمل الحقول الفارغة ويحافظ على المعلومات الموجودة؛ الهوية غير الصالحة تبقى للمراجعة.
3. من **المستخدمين** ينشئ حسابًا بدور **موظف** ويربطه بالملف الصحيح. تظهر كلمة مرور مؤقتة مرة واحدة، ويُطلب تغييرها عند أول دخول. تسلَّم لصاحبها عبر قناة المستشفى المعتمدة.
4. يدخل الموظف إلى **بوابة الموظف** ليرى اكتمال ملفه، ويحجز موعدًا، ويقدم طلب تصحيح بيانات أو خدمة، ويطلع على النتائج التي اعتمد الفريق مشاركتها معه.
5. يسجل الفريق حضور الموعد؛ يفتح النظام زيارة مرتبطة به. يوثق الممارس الشكوى والعلامات الحيوية والتقييم والخطة، ثم يكمل الزيارة فيتحدث الموعد تلقائيًا.
6. يسجل الفريق النتائج يدويًا أو يرفع تقرير المختبر. تمر النتائج المستخرجة بمراجعة بشرية قبل حفظها في الملف. مشاركة النتيجة مع الموظف خطوة مستقلة، والنتيجة الحرجة تتطلب توثيق التبليغ أولًا.

## الخدمات والإعدادات

توجد خدمات قابلة للتعديل والتفعيل من لوحة المدير: الاستشارة، المتابعة، الصحة المهنية، التطعيم، فحص ما قبل التوظيف، مراجعة نتائج المختبر، وطلبات السجلات. يستطيع المدير إضافة خدمة جديدة بنمط موعد أو طلب، مع وصف عربي وإنجليزي ومدة الزيارة وترتيب العرض.

المواعيد محسوبة بتوقيت الرياض. فحص السعة والحجز والإلغاء وإغلاق الفترات يتم داخل معاملات قاعدة البيانات لمنع التعارض. إكمال الملف يُحسب من الحقول التي اختارها المدير، وليس نسبة ثابتة في الواجهة. الإشعارات داخل النظام مرتبطة بالحجوزات والطلبات والنتائج المنشورة؛ لا تُرسل رسائل SMS أو بريد تلقائيًا.

## الصلاحيات

| الدور    | الوصول                                                                                                           |
| -------- | ---------------------------------------------------------------------------------------------------------------- |
| ADMIN    | إدارة العيادة والملفات والسجلات والاستيراد والمستخدمين والإعدادات والتدقيق                                       |
| STAFF    | الملفات والرعاية السريرية والمواعيد والطلبات والتقارير التفصيلية، دون إدارة المستخدمين أو استيراد تقارير المختبر |
| VIEWER   | مؤشرات وتقارير مجمعة؛ لا أسماء موظفين أو تشخيصات أو نتائج فردية                                                  |
| EMPLOYEE | ملفه المنشور ومواعيده وطلباته وإشعاراته فقط                                                                      |

المصادقة بحسابات التطبيق وكلمات مرور bcrypt وجلسات httpOnly، مع تحقق TOTP اختياري. قاعدة البيانات تعيد فحص نشاط الحساب وصلاحياته وإصدار جلساته في كل طلب. يوجد حد خمول 15 دقيقة وحد جلسة مطلق 12 ساعة. تغيير الدور أو كلمة المرور أو تعطيل الحساب يبطل الجلسات السابقة. أرشفة الملف أو إنهاء الخدمة يعطل حساب الموظف ويلغي مواعيده المفتوحة.

جداول Supabase محمية بـRLS؛ أدوار Data API العامة `anon` و`authenticated` لا تحصل على صلاحيات السجلات. الاتصال السريري يتم على الخادم فقط عبر Prisma. لا تضع رابط قاعدة البيانات أو سر الجلسة في متغير `NEXT_PUBLIC_*`.

## استيراد المختبر والمستندات

- الملفات حتى 50 MiB، بأجزاء 3 MiB مع إزاحة وبصمة SHA-256. إعادة إرسال الجزء لا تضاعف حجمه، والجزء المختلف في الإزاحة نفسها يُرفض. الحفظ النهائي يتحقق من اكتمال الملف وبصمته وتوقيعه.
- تقارير PDF النصية تُقرأ محليًا على الخادم مع الحفاظ على `<` و`>` والوحدة والنتائج السلبية. الصفحات غير المقروءة تُعرض للمراجعة اليدوية. الصور والمسح الضوئي يدعمان النسخ اليدوي من المستند.
- المطابقة برقم هوية صالح وملف موجود. لا يُنشأ موظف تلقائيًا من نتيجة مختبر. المراجع يحدد الموظف والفحص والقيمة والوحدة والتاريخ، ويُحفظ اسمه وتوقيت المراجعة.
- الملف الأصلي يبقى محفوظًا. العرض والتنزيل مصادقان، وتُقرأ الملفات الكبيرة بأجزاء صغيرة. المستندات متعددة الموظفين متاحة للفريق المصرح فقط.
- الحفظ المتكرر للدفعة لا ينشئ نتائج مكررة. البصمة الدلالية تمنع تكرار النتيجة نفسها من نسخ التقرير نفسه.
- الاستخراج الخارجي اختياري ومعطل افتراضيًا. يتطلب `ENABLE_AI_IMPORT=true` و`ANTHROPIC_API_KEY` و`LAB_EXTRACTION_MODEL` بعد تحديد مزود ومعالجة بيانات معتمدة. لا يُفترض اسم نموذج أو سعر خدمة.

## سلامة السجل

السجلات الطبية تُؤرشف أو تُعلّم **أُدخلت بالخطأ** مع سبب. حواجز قاعدة البيانات تمنع حذف السجلات الطبية وتعديل أو حذف سجل التدقيق. الزيارات تحمل رقم مراجعة لمنع الكتابة فوق تعديل أحدث. كل عملية كتابة سريرية مع سجل تدقيقها في معاملة واحدة.

قواعد التحاليل محددة بالإصدار والوحدة، ولا تنقل مدى مرجعيًا بين وحدات مختلفة. النتيجة غير المحسومة تُحال للمراجعة. مؤشرات التهاب الكبد B لا تشخص عدوى ولا تستنتج عدم الاستجابة من عدد صفوف التطعيم. توثيق الاستجابة يتطلب جرعات موثقة وتوقيتًا ووحدة مناسبة ونتيجة راجعها الممارس. مراجع التصميم: [CDC: إدارة تعرض العاملين لالتهاب الكبد B](https://www.cdc.gov/hepatitis-b/hcp/infection-control/index.html)، [CDC Pink Book: Hepatitis B](https://www.cdc.gov/pinkbook/hcp/table-of-contents/chapter-10-hepatitis-b.html). تعتمد القرارات السريرية النهائية على مراجعة الفريق وسياسة المستشفى.

## التشغيل والتطوير

يتطلب Node.js 22.13 أو أحدث وnpm. انسخ `.env.example` إلى `.env` واملأ القيم الخاصة ببيئة التطوير، ثم:

```bash
npm ci
npm run db:deploy
npm run dev
```

عند إنشاء قاعدة جديدة تمامًا، افتح `/setup` واستخدم `SETUP_TOKEN` لإنشاء المسؤول الأول، أو اضبط `SEED_ADMIN_USERNAME` و`SEED_ADMIN_PASSWORD` ثم شغّل `npm run db:seed`. لا توجد كلمة مرور افتراضية ولا بيانات موظفين تجريبية في أمر البذر. التهيئة مغلقة عند وجود مستخدمين، ولا تعيد إنشاء المسؤولين الحاليين.

| المتغير                                  | الغرض                                                     |
| ---------------------------------------- | --------------------------------------------------------- |
| DATABASE_URL                             | اتصال PostgreSQL عبر Supabase Transaction Pooler للتطبيق  |
| DIRECT_URL                               | اتصال Direct أو Session Pooler للهجرات؛ لا تضع قيمة فارغة |
| AUTH_SECRET                              | مفتاح عشوائي طويل، 32 حرفًا على الأقل، لتوقيع الجلسات     |
| SETUP_TOKEN                              | رمز التهيئة لقاعدة جديدة فقط                              |
| ENABLE_AI_IMPORT                         | false افتراضيًا؛ تفعيل المعالجة الخارجية اختياري          |
| ANTHROPIC_API_KEY / LAB_EXTRACTION_MODEL | مطلوبان مع التفعيل الصريح للاستخراج الخارجي               |

لا يحتاج التطبيق مفاتيح Supabase عامة في المتصفح. يحتفظ المشروع الحالي بقاعدة Supabase واتصال Vercel القائمين. `vercel.json` يستخدم منطقة `bom1` وأمر `npm run vercel-build` الذي يولد Prisma ويطبق الهجرات قبل البناء. الهجرات الجديدة إضافية وتحافظ على الملفات والحسابات الحالية.

## التحقق

```bash
npm run typecheck
npm run lint
npm test
npm run test:integration
npm run build
npm run test:production
```

اختبارات الدقة تغطي الأرقام والوحدات والنتائج السلبية والجرعات والتوقيت وقراءة PDF وExcel. اختبارات التكامل تشغل Next.js وقاعدة PGlite مؤقتة، ثم ترسل نماذج HTTP فعلية لتسجيل الدخول والحجز والزيارة والتحاليل والطلبات والرفع. تتحقق من البيانات الناتجة والصلاحيات والتكرار والحواجز على مستوى قاعدة البيانات. لا تتصل بقاعدة الإنتاج ولا تستخدم سجلات موظفين حقيقية. مجلد `.test-database` مؤقت ومستثنى من Git. CI يشغّل هذه البوابات على طلبات الدمج وmain؛ الفحص البصري على المتصفح يظل خطوة مستقلة عند تغيير الواجهة.

## النشر والاسترجاع

1. راجع الفرق وشغّل الاختبارات قبل الدمج. احتفظ بنسخة احتياطية من قاعدة البيانات قبل أي تغيير بنيوي لاحق.
2. ادمج في main وتابع بناء Vercel؛ `/api/health` يؤكد استجابة التطبيق واتصال قاعدة البيانات دون كشف السجلات.
3. تحقق من تسجيل الدخول، والأدوار، والحجز، ومراجعة المختبر في بيئة اختبار مناسبة. لا تنشئ سجلات طبية وهمية في الإنتاج.
4. عند الحاجة لاسترجاع التطبيق، أعد نشر إصدار Vercel السابق. لا تعكس هجرات البيانات تلقائيًا ولا تحذف جداول جديدة تحتوي سجلات. هجرات هذا الإصدار إضافية لتتيح استرجاع الكود مع إبقاء البيانات.

واجهة RTL عربية افتراضيًا مع الإنجليزية، ووضعين فاتح وداكن، وألوان قابلة للاختيار، وحركة تراعي إعداد تقليل الحركة، وتخطيط للجوال والطباعة. ملفات التصميم الرئيسية: `src/app/platform.css` و`src/components/layout/Shell.tsx`؛ إعدادات العيادة في `src/lib/clinic-config.ts`؛ الصلاحيات في `src/lib/auth/rbac.ts`؛ قواعد الرعاية في `src/lib/clinical`.
