## ما هو هذا النظام

منصة داخلية لإدارة عيادة الموظف: ملف صحي إلكتروني لكل موظف يجمع الزيارات والتحاليل
والحساسية والتحصينات والتثقيف الصحي، مع **محرّك استحقاق** يخبرك بما يجب عمله اليوم،
و**استيراد ذكي** لتقارير المختبر يقرأ ملف PDF ويستخرج النتائج للمراجعة البشرية قبل حفظها.

### المبادئ الحاكمة في التصميم

| المبدأ | كيف طُبّق |
|---|---|
| **لا حذف لأي سجل طبي** | الأرشفة والتعليم كـ«أُدخل بالخطأ» فقط؛ لا يوجد مسار حذف في الكود |
| **النموذج يستخرج، النظام يفسّر** | الذكاء الاصطناعي ينسخ القيم والوحدات فقط؛ الدلالة والحرجية والمناعة تُحسب بقواعد ثابتة في `src/lib/clinical` |
| **لا حفظ آلي في السجل الصحي** | كل نتيجة مستوردة تمر بشاشة مراجعة، ولا يُنشأ ملف موظف تلقائياً أبداً |
| **صلاحيات الطبيب ≠ صلاحيات الإدارة** | دور «الاطلاع الإداري» يرى مؤشرات مجمّعة فقط، بلا تشخيص أو نتيجة تحليل |
| **مؤشرات قابلة للتنفيذ** | «١٢ جرعة متأخرة» مع أسماء قابلة للنقر، بدل «نسبة التحصين ٧٨٪» |
| **كل عملية مسجّلة** | سجل تدقيق يُضاف إليه فقط، بلا مسار تعديل أو حذف حتى للمسؤول |

## البدء السريع محلياً

```bash
npm install
cp .env.example .env          # ثم املأ DATABASE_URL و AUTH_SECRET و SETUP_TOKEN
npx prisma migrate deploy
npm run db:seed               # مسؤول + ٢٤ موظفاً تجريبياً (اختياري)
npm run dev
```

بيانات الدخول بعد `db:seed`: المستخدم `admin` وكلمة المرور من `SEED_ADMIN_PASSWORD`
(الافتراضية `ChangeMe2026!`)، وسيُطلب تغييرها عند أول دخول.

بدون بذر البيانات، افتح `/setup` وأدخل قيمة `SETUP_TOKEN` لإنشاء حساب المسؤول الأول.
تُغلق صفحة التهيئة نهائياً بمجرد وجود أي مستخدم.

## النشر على Vercel

### 1. قاعدة البيانات

أنشئ قاعدة PostgreSQL. الأسهل من داخل Vercel: **Storage → Create → Neon Postgres**.
اختر أقرب منطقة جغرافية متاحة لمكان العمل (`eu-central-1` فرانكفورت هي الأقرب للمملكة).

### 2. متغيرات البيئة

في **Project → Settings → Environment Variables**:

| المتغير | القيمة |
|---|---|
| `DATABASE_URL` | رابط الاتصال المجمّع (pooled) من Neon |
| `DIRECT_URL` | رابط الاتصال المباشر من Neon — تستخدمه الهجرات فقط |
| `AUTH_SECRET` | `openssl rand -base64 48` |
| `SETUP_TOKEN` | قيمة عشوائية طويلة لإنشاء أول مسؤول |
| `ENABLE_AI_IMPORT` | `false` (أو `true` بعد اعتماد المعالجة الخارجية) |
| `ANTHROPIC_API_KEY` | مطلوب فقط عند تفعيل الاستيراد الذكي |

### 3. النشر

ادفع المستودع إلى GitHub واستورده في Vercel. لا حاجة لأي إعداد إضافي:
`vercel.json` يضبط أمر البناء ومنطقة التشغيل، وأمر البناء ينفّذ
`prisma generate && prisma migrate deploy && next build` — أي أن الهجرات تُطبَّق تلقائياً
مع كل نشر.

### 4. أول دخول

افتح `https://<your-app>.vercel.app/setup` وأدخل `SETUP_TOKEN`.

> **ملاحظة على إقامة البيانات:** لا توجد منطقة Vercel داخل المملكة، وقد ضُبط
> `vercel.json` على `fra1` (فرانكفورت) كأقرب خيار. إن كان إبقاء البيانات الصحية داخل
> المملكة شرطاً، فالنظام يعمل كما هو على أي خادم يشغّل Docker أو Node — والتغيير في
> طريقة النشر فقط، لا في الكود.

## نظرة على النظام

### الوحدات

- **لوحة التحكم** — بنود «يحتاج إجراء» أولاً، ثم المؤشرات العامة والرسوم
- **الموظفون** — بحث، عرض شبكي/قائمة، ملف صحي بسبعة تبويبات، استيراد Excel للتحميل الأولي
- **الزيارات** — نوع الزيارة، الشكوى، العلامات الحيوية بأعمدة مستقلة، التشخيص والخطة
- **التحاليل** — نتائج مهيكلة (قيمة + وحدة + مدى مرجعي + دلالة محسوبة)، طوابير النتائج الحرجة والمراجعة
- **استيراد التقارير** — رفع PDF/صورة، استخراج، مطابقة هوية، شاشة مراجعة مقسومة، حفظ المعتمَد فقط
- **التحصينات** — سلاسل الجرعات، حساب الجرعة القادمة، تغطية حسب اللقاح
- **المستحقات** — كل ما هو متأخر أو مستحق أو قريب، بالاسم والإجراء
- **التقارير** — ستة تقارير مع تصدير Excel وطباعة
- **المستخدمون وسجل التدقيق** — إدارة الحسابات والتحقق الثنائي، وسجل غير قابل للتعديل

### الأدوار

| الدور | الصلاحيات |
|---|---|
| `ADMIN` — مسؤول العيادة | كل شيء، بما فيه الاستيراد وإدارة المستخدمين وسجل التدقيق |
| `STAFF` — ممرض/فني | إدخال البيانات السريرية، بلا أرشفة ولا استيراد ولا إدارة مستخدمين |
| `VIEWER` — اطلاع إداري | مؤشرات مجمّعة فقط: بلا تشخيص، بلا نتيجة تحليل، بلا ملاحظة |

### الأمان

- جلسات JWT في كوكي `httpOnly` مع خمول ١٥ دقيقة وحد أقصى ١٢ ساعة
- تجزئة كلمات المرور بـ bcrypt، وقفل الحساب بعد ٥ محاولات فاشلة
- تحقق ثنائي TOTP اختياري، ومنبَّه عليه للمسؤولين
- إبطال كل الجلسات عند تغيير كلمة المرور أو الدور أو التعطيل
- المرفقات تُخدَّم عبر مسار مصادَق ومسجَّل فقط — لا رابط عام لأي مستند
- كل اطلاع على ملف يحتوي نتائج مصلية حساسة يُكتب في سجل التدقيق

## الاستيراد الذكي لتقارير المختبر

مُعطَّل افتراضياً. عند تفعيله:

1. يُخزَّن الملف الأصلي في قاعدة البيانات ولا يُعدَّل أبداً
2. يُرسَل كمستند PDF أصلي إلى `claude-opus-5` — لا OCR ولا تعابير نمطية
3. يعيد النموذج سجلات مهيكلة عبر أداة صارمة (`strict: true`)، وكل سجل يحمل **رقم الصفحة**
   و**اقتباساً حرفياً** من التقرير و**درجة ثقة**
4. يتحقق النظام حسابياً: صحة رقم الهوية، وجود القيمة، منطقية التاريخ، انتماء التحليل للدليل
5. المطابقة برقم الهوية فقط تُربط تلقائياً؛ التشابه بالاسم يُقترح؛ وما عداه يذهب لقائمة
   **«غير مطابَق»** — ولا يُنشأ ملف موظف تلقائياً أبداً
6. شاشة مراجعة مقسومة: التقرير الأصلي على جانب والحقول القابلة للتعديل على الآخر
7. لا يصل شيء إلى ملف صحي إلا بعد اعتماد شخص محدَّد بالاسم

التكلفة التقديرية ~٤ سنتات لكل صفحة تقرير.

> إرسال تقارير تحمل أسماء وأرقام هويات إلى خدمة خارجية هو نقل بيانات صحية لطرف ثالث.
> لا تفعّل هذه الوحدة قبل الحصول على موافقة مكتوبة من الجهة. النظام كامل الوظائف بدونها.

## بنية المشروع

```
prisma/
  schema.prisma            نموذج البيانات + قواعد التصميم كتعليقات
  seed.ts                  حساب المسؤول + بيانات تجريبية
src/
  app/
    (app)/                 الصفحات خلف تسجيل الدخول
    api/                   المرفقات، التصدير، الفحص الصحي، تسجيل الخروج
    login · setup · account/password
  components/              الواجهة: بطاقات، جداول، نماذج، رسوم
  lib/
    catalog/               دليل التحاليل واللقاحات (المفردات المعتمدة)
    clinical/              محرك القواعد: الدلالات، مناعة HBV، الاستحقاق
    auth/                  الجلسات، الأدوار، كلمات المرور، TOTP
    ai/extract.ts          استخراج تقارير المختبر
    i18n/                  القاموس العربي/الإنجليزي
  server/
    actions/               عمليات الكتابة (Server Actions)
    queries/               الاستعلامات المشتركة
```
